# 01. Видение продукта и требования

## Цель
Мобильное приложение (iOS + Android), которое в реальном времени с камеры
телефона определяет, какие шары игры в петанк лежат ближе всего к кошонету,
показывает расстояния и подсвечивает шары на экране.

## Целевой пользователь
Игрок в петанк, который хочет быстро и без рулетки разрешить спорную ситуацию
«чей шар ближе» или просто видеть расклад в процессе партии.

## Ключевые сценарии (use cases)
1. **Быстрая проверка ближайшего шара.** Игрок наводит камеру с расстояния
   ~1.5–4 м, приложение выделяет кошонет, нумерует шары по близости и
   показывает дистанции в сантиметрах.
2. **Подсказка по позиционированию.** Если угол наклона, освещение или
   перекрытие не дают точно посчитать, приложение подсказывает: «отойдите на
   полметра», «опустите камеру ниже», «обойдите с другой стороны».
3. **Настройка визуала.** Игрок включает/выключает слои: bbox, номера,
   дистанции, линии до кошонета, окружности, отладочную AR-сетку.
4. **(Этап 2) Подсчёт игры.** Приложение различает шары двух команд (по
   цвету/рисунку) и автоматически считает очки в концу мене (mène).

## Функциональные требования

### Должно быть в MVP
- F1. Real-time детекция шаров и кошонета на видеопотоке (≥15 FPS на среднем
  телефоне).
- F2. Оценка дистанции от каждого шара до кошонета в метрах/см с указанием
  погрешности.
- F3. Сортировка шаров по близости и нумерация (1, 2, 3…).
- F4. Оверлей с настраиваемыми слоями: bounding box, номер, дистанция, линии,
  окружность вокруг кошонета.
- F5. Индикатор качества измерения (зелёный/жёлтый/красный) на основе угла
  наклона, видимости плоскости земли, числа найденных объектов.
- F6. Подсказки по позиционированию камеры.
- F7. Заморозка кадра («снимок») для детального изучения.

### Этап 2 (post-MVP)
- F8. Привязка шаров к командам по цвету/насечкам.
- F9. Подсчёт очков в текущем мене.
- F10. История партий, экспорт.
- F11. Калибровка модели под конкретные шары пользователя (фото-калибровка).

### Не входит в MVP
- Мультиплеер, синхронизация между телефонами.
- Распознавание игроков по лицам.
- Оффлайн-карты площадок.

## Нефункциональные требования
- **NF1. Производительность:** ≥15 FPS детекции на iPhone 12 / Pixel 6.
- **NF2. Точность дистанций:** на дистанциях 1–6 м погрешность не более ±5%
  при правильном позиционировании камеры.
- **NF3. Приватность:** все вычисления и видео — локально на устройстве.
  Никакой отправки кадров на сервер в MVP.
- **NF4. Оффлайн:** работает без интернета.
- **NF5. Размер пакета:** на iOS — < 80 МБ, на Android — < 60 МБ
  (с упакованной ML-моделью).

## Ограничения и риски
- **R1.** Точная оценка расстояния по монокулярной камере на дистанциях
  > 6 м деградирует. → подсказки по позиционированию и индикатор качества.
- **R2.** Кошонет (jack, ~30 мм) сильно меньше шаров и сливается с грунтом.
  → может потребоваться отдельный класс детекции и/или явная процедура
  «кликнуть на кошонет».
- **R3.** Тени, песок, гравий, мокрый грунт — каждый из вариантов фона может
  потребовать дообучения модели. → план сбора и разметки датасета.
- **R4.** Перекрытия шаров (один за другим) — частая ситуация. → инструкция
  пользователю обойти с другой стороны + детекция occlusion-кейсов.

## Стандартные размеры (для геометрической оценки дистанции)
- Шар (boule): диаметр 70.5–80.0 мм (FIPJP). По умолчанию принимаем 74 мм,
  даём настройку.
- Кошонет (but/jack): диаметр 30 мм (допуск 28–32 мм по правилам).
- Эти числа — единственная «априорная» информация, которая позволяет считать
  дистанцию даже без AR.
