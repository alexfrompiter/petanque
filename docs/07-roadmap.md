# 07. Поэтапный план разработки

Цель — раскладка работ по фазам с измеримыми критериями выхода из каждой
фазы. Длительности — оценочные, для команды из 2 разработчиков (iOS + Android)
+ 1 ML-инженера на парт-тайм.

---

## P0. Скелет проектов и инфраструктура (1 неделя)

**Делаем.**
- Создаём `ios/` (Xcode project, SwiftUI app, минимальный CameraView).
- Создаём `android/` (Android Studio project, Compose app, CameraX preview).
- Настраиваем CI: SwiftLint + xcodebuild test на iOS, ktlint + gradle test на
  Android.
- Создаём `ml/` со скелетом обучения (заглушка, ещё без модели).
- `shared/schema/` — JSON-схемы `SceneState` и `OverlaySettings`.

**Критерии выхода.**
- На обеих платформах запускается приложение, камера показывает preview.
- CI зелёный.
- README ссылается на эти док-файлы.

---

## P1. Детекция шаров (2–3 недели)

**Делаем.**
- Собираем первый набор данных (500–1000 кадров), размечаем boule/cochonnet.
- Тренируем YOLOv8n, экспортируем в CoreML и TFLite.
- Подключаем модель в обоих приложениях, рисуем bbox поверх preview.
- Tracker между кадрами (Kalman или ByteTrack-light).

**Критерии выхода.**
- mAP@50 ≥ 0.80 для boule, ≥ 0.65 для cochonnet на eval-сетке.
- ≥ 15 FPS на iPhone 12 и Pixel 6.
- В UI: bbox-оверлей со стабильными ID шаров между кадрами.
- Никаких дистанций ещё нет — только обнаружение и подсветка.

---

## P2. Дистанции через AR (2–3 недели)

**Делаем.**
- Подключаем ARKit (iOS) и ARCore (Android). Запускаем AR-сессию параллельно
  с потоком детекций.
- Реализуем метод A (AR plane + hit-test) в `DistanceEstimator`.
- Считаем евклидовы расстояния от кошонета и ранжируем шары.
- Снимаем 20–30 тестовых сцен с эталонными измерениями рулеткой.
- Прогоняем офлайн-валидацию.

**Критерии выхода.**
- MAE < 8% на дистанциях 1–4 м (метод A в одиночку).
- В UI: номера ранга и текст дистанции возле шаров.
- Базовый QualityScorer работает (3 уровня: зелёный/жёлтый/красный).

---

## P3. Геометрия + Fusion + подсказки (2 недели)

**Делаем.**
- Метод B (геометрия по диаметру) + интеграция IMU (pitch).
- Fusion (см. `04-distance-estimation.md`).
- HintsEngine: правила подсказок и баннер снизу.
- Опционально: LiDAR-метод на поддерживающих iPhone.

**Критерии выхода.**
- MAE < 5% (fusion) на дистанциях 1–6 м.
- Подсказки появляются в нужных условиях.
- На устройствах без AR — fallback на геометрию работает.

---

## P4. Полировка UI и слои (1–2 недели)

**Делаем.**
- Реализуем все слои оверлея (`circles`, `lines`, `arDebug`, `quality`).
- Настройки слоёв с сохранением.
- Frozen mode + share screenshot.
- Пустые состояния и обработка ошибок.
- Доступность (VoiceOver/TalkBack, dynamic type).
- Локализация на ru / en / fr (фр — целевая аудитория петанка).

**Критерии выхода.**
- Все слои работают и тогглятся независимо.
- Внутренний UX-ревью пройден (5–10 тест-пользователей).

---

## P5. Beta-релизы (2 недели)

**Делаем.**
- TestFlight (iOS) и Google Play Internal Testing (Android).
- Telemetry-минимум: счётчики ошибок (Sentry или Firebase Crashlytics).
  **Без отправки кадров и без идентификации пользователя.**
- Сбор фидбэка от 10–30 бета-тестеров.
- Поправки модели по реальным проблемным сценам.

**Критерии выхода.**
- < 1% crash-free sessions падений.
- NPS среди бета-тестеров > 30.

---

## P6. Командная принадлежность и счёт (post-MVP, 3–4 недели)

**Делаем.**
- Тренируем дополнительную «голову» классификации шара по принадлежности
  (команда A / команда B) — либо по доминирующему цвету (HSV-эвристика +
  легкий классификатор), либо по узору (отдельный CNN-классификатор на crop).
- UI-флоу «новый мене» → пользователь подтверждает раскраску → автоматический
  подсчёт очков по правилам петанка (все шары победившей команды, которые
  ближе ближайшего проигравшего, дают по 1 очку).
- Счётчик партии (до 13).
- Локальная история партий (SQLite).

**Критерии выхода.**
- Корректное автоматическое определение цвета шара ≥ 90%.
- Подсчёт очков совпадает с ручным в ≥ 95% случаев тест-партий.

---

## P7. Дальнейшее развитие (бэклог, без сроков)

- Multi-frame averaging (стабилизация дистанций между кадрами).
- Облачная синхронизация партий между устройствами.
- Социальные функции (поделиться партией, профиль игрока).
- Веб-просмотр истории.
- Apple Watch / Wear OS компаньон.
- Поддержка bocce, lawn bowls (родственные игры).

---

## Зависимости между фазами

```
P0 ─┬─► P1 ─► P2 ─► P3 ─► P4 ─► P5 ─► P6
    │
    └─► ml/ (датасет идёт параллельно с P1, расширяется на P2-P3)
```

P6 идёт уже после релиза MVP и может стартовать параллельно с P5, если
ML-ресурс свободен.
