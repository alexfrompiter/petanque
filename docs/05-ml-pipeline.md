# 05. ML-пайплайн: датасет, обучение, экспорт

## Цель модели
Детектор объектов с двумя классами:
- `boule` — игровой шар (любого цвета/рисунка; разделение по командам —
  отдельный шаг на этапе 2).
- `cochonnet` — целевой шар (маленький, обычно деревянный, ярких цветов).

Выходной формат — стандартный для object detection: `[x, y, w, h, class, score]`
в координатах входного тензора (640×640), затем масштабируем обратно в кадр.

## Архитектура

- **MVP:** YOLOv8n или YOLOv11n (3–4M параметров). Лёгкая, есть готовые
  экспортёры в CoreML и TFLite, хорошо квантуется в int8.
- **Альтернатива:** RT-DETR-small если будет проседать на маленьком кошонете.

Бюджет на инференс: ≤ 60 мс на iPhone 12 (CoreML с Neural Engine), ≤ 80 мс
на Pixel 6 (TFLite GPU delegate). Целимся ≥15 FPS детекции с учётом
препроцессинга/постпроцессинга.

## Датасет

### Размер
- Этап P1 (доказательство концепции): 500–1000 размеченных кадров.
- Этап MVP: 3000–5000 размеченных кадров.

### Источники
1. **Самозапись:** видеоролики реальных партий с разных площадок (песок,
   гравий, утрамбованная глина), разное освещение (утро/полдень/закат),
   с разных углов.
2. **Чужие данные:** YouTube-видео турниров FIPJP, лицензионно очищенные
   стоковые видео. Использовать только для обучения, не для распространения.
3. **Аугментация:** Albumentations — повороты до 25°, изменение яркости,
   контраста, добавление теней, синтетический «песок» / «гравий».

### Что снимать
- Дистанции до камеры: 1–8 м.
- Углы наклона: 20°, 35°, 50°, 70°.
- Количество шаров в кадре: 1–12.
- Сценарии: чистая площадка, перекрытия, шар у борта, кошонет в полутени.

### Разметка
- Инструмент: [CVAT](https://www.cvat.ai/) (локально, Docker) или Roboflow
  Annotate.
- Гайдлайн разметки → `docs/labeling-guide.md` (написать на старте сбора).
  Ключевые правила:
  - Bbox охватывает видимую часть шара (без отбрасываемой тени).
  - Перекрытый > 50% шар помечается атрибутом `occluded=true`.
  - Кошонет всегда отдельный класс, даже если близко к шару.

### Хранение
- Сырые изображения и аннотации **вне git** (большие).
- В репо — манифесты (CSV/Parquet со списком файлов + хэшами) и `README.md`
  с инструкцией, как развернуть датасет локально.
- Облако: рекомендация — S3-compatible (Backblaze B2 или DigitalOcean Spaces),
  тайм-стампы версий датасета.

## Тренировка

`ml/train/train.py`:
```bash
yolo task=detect mode=train \
     model=yolov8n.pt \
     data=ml/data/petanque.yaml \
     imgsz=640 epochs=200 batch=32 \
     project=runs/petanque name=v1
```

Параметры:
- `imgsz=640` — стандарт. Если кошонет теряется, попробовать 768/896.
- Early stopping по mAP@50 на валидации (15 эпох без улучшения).
- Метрика для критерия выпуска: **mAP@50 ≥ 0.85** для `boule`,
  **mAP@50 ≥ 0.75** для `cochonnet` (он мельче и сложнее).

## Экспорт

`ml/export/export.py`:
```bash
# CoreML (iOS) — fp16
yolo export model=runs/petanque/v1/weights/best.pt format=coreml half=True nms=True

# TFLite (Android) — int8 quantized
yolo export model=runs/petanque/v1/weights/best.pt format=tflite int8=True nms=True
```

Артефакты:
- `ios/Petanque/Resources/PetanqueDetector.mlpackage`
- `android/app/src/main/assets/petanque_detector.tflite`

Хранение версий моделей: Git LFS либо отдельные GitHub Releases (теги
`model-v1`, `model-v1.1`, …). В каждом релизе — обе модели и `metrics.json`
с показателями на eval-сетке.

## Тест-сет для регрессий

Отдельный «золотой» набор из ~200 кадров, никогда не попадающий в обучение.
CI-задача: при коммите новой модели прогоняет её на этом наборе и сравнивает
mAP с baseline. Регрессия > 3% — фейл.

## Калибровка на конкретный набор шаров (этап 2, опционально)

Пользователь делает 1 эталонное фото своих шаров рядом с кошонетом с
известного расстояния. Приложение:
- проверяет реальный диаметр пользовательских шаров (можно отличаться от 74 мм),
- сохраняет это в настройках, использует в методе геометрии,
- опционально — fine-tune CoreML/TFLite модели on-device (Apple это
  поддерживает через `MLUpdateTask`).
