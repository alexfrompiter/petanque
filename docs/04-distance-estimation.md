# 04. Оценка расстояния (технический разбор)

Это самый рискованный технический узел проекта. Здесь — три метода, как их
комбинировать и какую точность ожидать.

## Метод A. AR plane + hit-test (основной)

**Идея.** ARKit/ARCore во время сессии находит горизонтальные плоскости (грунт,
песок, гравий). Для каждой детекции в кадре берём точку **основания** шара
(середина нижней грани bbox) и делаем raycast/hit-test по этой плоскости.
Получаем точку в 3D-мире, в метрах, относительно сессии.

**Плюсы.**
- Не зависит от размера шара, работает с любыми объектами на земле.
- Учитывает наклон и подъёмы поверхности.
- На дистанциях 1–6 м даёт 2–5% погрешности.

**Минусы.**
- Нужно «прогреть» AR-сессию (помахать телефоном, чтобы найти плоскость).
- На однотонных поверхностях (чистый песок) плоскость может не найтись.
- Точка основания шара ≠ точка касания плоскости (шар лежит частично в
  углублении). Корректируем: после hit-test поднимаем точку центра шара на
  `r = 37 мм` и проецируем обратно — даёт <1% поправку.

**Реализация.**
- iOS: `ARView.raycast(from:allowing:alignment:)` или
  `ARSession.raycast(_:)` с `.estimatedPlane` / `.existingPlaneGeometry`.
- Android: `Frame.hitTest(x, y)` → перебираем `HitResult`, берём первый
  `Plane` с `Plane.Type.HORIZONTAL_UPWARD_FACING`.

## Метод B. Геометрия по известному размеру шара (запасной)

**Идея.** Шар диаметром `D` (известно), проекция в кадре имеет диаметр `d`
пикселей, фокусное расстояние камеры `f` пикселей. Расстояние до шара:

```
Z ≈ f * D / d
```

Это даёт **расстояние вдоль оптической оси**. Чтобы получить дистанцию по
поверхности земли, нужно знать угол наклона камеры θ (pitch) от IMU:

```
distance_on_ground ≈ Z * cos(θ_to_ball)
```

где `θ_to_ball` учитывает и pitch камеры, и угловую позицию шара в кадре.

**Плюсы.**
- Работает на любом телефоне без AR.
- Не нужно искать плоскость.

**Минусы.**
- Зависит от точности bbox. Ошибка в 2 пикселя для шара 30px → ~7% ошибки
  в дистанции.
- Не работает для перекрытых шаров (bbox обрезан).
- На дистанциях > 6 м шар занимает мало пикселей — ошибка растёт нелинейно.

**Калибровка.** `f` берём из intrinsics камеры:
- iOS: `ARFrame.camera.intrinsics` или `AVCaptureDevice` lens calibration.
- Android: `Camera.getCameraInfo()` + `CameraIntrinsics` (ARCore), либо
  `CameraCharacteristics.LENS_INTRINSIC_CALIBRATION`.

## Метод C. LiDAR depth (только на iPhone Pro/iPad Pro)

**Идея.** LiDAR-сенсор даёт depth map с разрешением ~256×192. Сэмплируем
глубину в центре bbox каждого шара → готовая 3D-точка.

**Плюсы.** Самая высокая точность, не нужны плоскости.

**Минусы.** Только часть устройств. На солнце депт-камера шумит.

**Использование.** Включаем как «секретный соус» там, где доступен. В оценке
качества это даёт +20 к scoring.

## Fusion-стратегия

```
def estimate(ball, ar_hit, geom, lidar):
    candidates = []
    if lidar:            candidates.append(('lidar', lidar, 0.9))
    if ar_hit:           candidates.append(('ar', ar_hit, 0.8))
    if geom:             candidates.append(('geometry', geom, 0.5))

    if not candidates:
        return None  # «не смог оценить»

    # Если есть >=2 — сравниваем; согласие → растёт уверенность
    primary = candidates[0]
    for method, value, _ in candidates[1:]:
        if abs(value.distance - primary[1].distance) / primary[1].distance < 0.1:
            primary = (primary[0], primary[1], min(1.0, primary[2] + 0.1))

    return primary
```

## Подсказки по позиционированию (для повышения точности)

| Условие | Подсказка |
|---|---|
| Pitch камеры > 70° (почти вертикально вниз) | «Поднимите телефон — снимайте чуть сверху» |
| Pitch камеры < 15° (почти горизонтально) | «Опустите телефон, нужен наклон ~40°» |
| AR-плоскость не найдена > 3 с | «Помашите телефоном медленно из стороны в сторону» |
| Кошонет не найден детектором | «Подойдите ближе или кликните по кошонету» |
| Шары перекрывают друг друга (IoU > 0.3) | «Обойдите площадку с другой стороны» |
| Дистанция до ближайшего шара > 6 м | «Подойдите ближе — точность падает» |
| Сильный засвет / низкая контрастность | «Сместитесь, чтобы солнце не было сзади» |

## Что нужно для валидации

1. Набор тестовых сцен (15–30 шт.) с **измеренными рулеткой** дистанциями
   от кошонета до 6 шаров. Снимать с разных углов и дистанций.
2. Скрипты в `ml/` для прогона офлайн-предсказаний по этим записям и
   построения таблицы «эталон vs предсказание» по каждому методу и fusion.
3. Целевая метрика MVP: **MAE < 5%** на дистанциях 1–6 м для **fusion**.
